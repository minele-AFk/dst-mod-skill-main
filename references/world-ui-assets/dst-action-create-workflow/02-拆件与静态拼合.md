# 02 拆件与静态拼合

核心顺序来自三狼案例中的明确纠正：**先决定拆分部件，再让选定的图像生成/编辑工具根据已确认三视图画对应部件，并让它们能与原图对上。** 三狼案例实际使用 image2，但本流程不要求其他项目使用同一工具。

## 1. 先写部件方案

按独立运动、关节、遮挡变化和换图需求拆分，不按颜色随意切块。每件至少记录：

| 字段 | 内容 |
|---|---|
| 个体与 `part_id` | 稳定唯一名称；左右是生物自身左右 |
| 视角 | 本次 `front / left / back` |
| 包含与排除 | 例如上头含眼耳和上牙，但不含活动下颌 |
| 父部件 | 颈接胸，头接颈，下颌接头；不等于最终骨骼控制层级 |
| 接头与活动 | 肩、肘、髋、膝、颌轴；预计转角和需要的覆盖余量 |
| 层级与显隐 | 哪些压在前面，哪些在某方向中被遮挡 |
| 原图位置 | 三视图画布位置、局部特征锚点、尺寸与朝向 |
| 状态附件 | 是否需要闭眼、受击表情、口腔内衬或其他换图 |

不确定的 pivot 标成待验证，不用图片中心或虚构坐标填满表格。关节极限动作需要的补画，应在这一阶段提出。

## 2. 本次完整清单

三只共同的 17 个部件：

```text
torso, pelvis, mane, tail_base, tail_tip
fore_left_upper, fore_left_lower, fore_left_paw
fore_right_upper, fore_right_lower, fore_right_paw
hind_left_upper, hind_left_lower, hind_left_paw
hind_right_upper, hind_right_lower, hind_right_paw
```

大狼额外 6 个：`neck_left, head_left, jaw_left, neck_right, head_right, jaw_right`。

小狼 A、B 各额外 3 个：`neck_main, head_main, jaw_main`。

| 个体 | 部件定义数 | 每件视角 | 实际 PNG 数 |
|---|---:|---:|---:|
| 双头大狼 `greater` | 23 | 3 | 69 |
| 小狼 A `small-a` | 20 | 3 | 60 |
| 小狼 B `small-b` | 20 | 3 | 60 |
| 合计 | 63 | 3 | 189 |

这是本次动作范围下的清单，不是所有生物的固定模板。闭眼附件没有包含在本次数量中。

## 3. 逐件生成

1. 先测试高风险连接，例如“颈 + 上头 + 下颌”和一条完整腿；确认方法可行后完成整张清单。
2. 每次明确一个部件名称，附该个体已确认的三视图，约束原有轮廓、颜色、视角和比例。
3. 可一次生成同一部件的三个方向，再导出三张 PNG；不能只交一张部件总览板。
4. 补足被遮挡的关节根部与覆盖面，保留完整生成轮廓；不能只留下静态姿势下可见的一小段。
5. 分清牙齿和口腔归属，防止上下颌重复牙齿、背面出现正脸、颈部夹带第二个头。
6. 保存原始生成图、实际提示词、模型标识、选定结果及编辑来源；本次记录为 `gpt-image-2`。
7. 最终导出独立 RGBA PNG，保留抗锯齿与透明余量。在深浅背景检查白边、残底和断线。

本次原始生成图采用色键背景，导出时去除背景。流程不强制新任务也使用绿底，关键是最终透明边可靠。不能把参考原图裁片贴回新图，掩盖生成部件不能对应的问题。

## 4. 配准和数据登记

以批准三视图坐标为基准，按可识别特征校准位置、尺度和必要的旋转。必要时回到图像工具重画，不靠大幅拉伸硬凑。

本次 manifest 中的关键约定：

- `source_sheet_placement_px` 是部件画布在原三视图中的起点，x 向右、y 向下。
- 导出 PNG 已烘焙相应旋转和缩放时，不得再次应用记录中的变换。
- `z_index_hint` 和 `pose_visible` 指示静止装配层级与可见性。
- 特征匹配残差、内点数量、几何估计方法只说明配准依据，不证明整件逐像素一致。
- 保存图片尺寸、来源和 SHA-256，防止新旧素材或不同个体混用。

图像坐标、骨架世界坐标和 SCML pivot 不是同一坐标系，转换时需要明确原点、y 轴和镜像规则。

## 5. G3 完整性验收

- 按“个体 x 部件 x 视角”对照清单检查，不能把三个小样称为全部完成。
- 每张图片实际存在、能解码、非空白、有正确透明通道。
- 总览中的每个部件都能对应到实际文件，保留可单独打开的三视图页。
- 在当前方向被遮住的部件仍交付文件，并标记隐藏；不能为了展示数量把它强行画在最上层。

## 6. 静态拼合与 G4 验收

1. 只使用交付 PNG、记录的位置、显隐和层级，生成每只的三个实际拼合视图。
2. 同坐标并排展示“批准原图 / 上版拼合 / 修订拼合”；可补叠加诊断，但不以诊断覆盖代替成品。
3. 先校正头身比例、脚宽、肩髋位置和地面接触，再处理局部色差、鬃毛重复、口腔和接缝。
4. 检查上肢-下肢、下肢-爪的连接，头颈、颌轴、尾段和躯干遮挡。
5. 缺画或画错的部件回到图像工具；仅位置或层级有问题则修装配数据。
6. 重新从 PNG 生成对照图、更新 manifest 和检查报告，交用户审查。

本次 V4 的 72 对腿部相邻关节在静态下有重叠，9 个拼合视图均有单个主体连通区域。这些结果不能证明旋转时不露缝，也不能证明外观已被用户接受。

## 7. 逐件提示词模板

```text
使用附件中已确认的【个体】C 风格三视图，绘制且只绘制【part_id】。
输出同一部件的 front / left / back 三个独立视图。
必须包含：【该部件的解剖范围】；不得包含：【相邻部件及重复内容】。
保持原图对应视角的比例、颜色、毛束轮廓、标记和面部身份。
允许补全：【指定隐藏接头】，用于绕【语义关节】转动时保持覆盖。
不要重新设计可见部分，不额外画完整角色，不用原图裁切蒙版代替绘制。
保留完整轮廓及边缘余量，不加入标签、边框、投影或场景。
```

三狼案例的完整解剖边界和修订装配记录分别保存在案例归档相对路径 `output/imagegen/2026-09-05-murk-wolf-C-complete-v3/delivery/PARTS_PLAN.md` 与 `output/imagegen/2026-09-05-murk-wolf-C-assembly-v4/delivery/manifest.json`。案例归档未随本仓库分发；新项目应在自己的项目根目录下保留同类计划和 manifest。
