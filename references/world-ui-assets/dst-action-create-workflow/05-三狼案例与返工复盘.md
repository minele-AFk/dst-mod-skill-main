## 1. 对话要求如何变成流程

| 用户要求或纠正 | 沉淀的规则 |
|---|---|
| 网页搜索三狼图片，image2 先做几版风格 | 先有真实身份参考，风格先试后定 |
| 把它们当作独立个体画三视图 | 每只独立文件与身份，不交一张群像代替 |
| 保留 C 夸张卡通风，删除其他风格 | 冻结选定基准，仅清理明确排除的风格 |
| 按保留的三视图创建生物拆分 | 拆件必须回到同一设计基准 |
| 先决定哪些部件，再让 image2 画对应部分 | 先部件方案，后逐件生成，并验证对应关系 |
| 每个部件的图呢；完成所有部件 | 交实际独立文件；样板和总览不等于完整交付 |
| 目前拼起来是什么样 | 用交付 PNG 实际装配，让问题可见 |
| 优化出现问题的地方 | 对照原图定位绘画、比例、位置、层级和接缝问题 |
| 用 OpenSpine 骨骼制作四面四类动作 | 工具研究、真实 rig、方向规则、动作和事件表 |
| 可以提出 OpenSpine 的问题 | 记录工具限制与复现依据，区分素材和制作错误 |
| 总结工作流程 | 沉淀可重复步骤，不把总结当作动画验收通过 |
| 正背面死亡要跪地，行走腿图和脚动作有问题 | 死亡按方向设计末姿；行走同时检查显隐、透视缩短、脚掌约束及支撑轨迹 |
| 正面攻击同向折腿，小狼背面攻击向内夹 | 按实际关节与解剖左右判断弯曲，正背面独立核对；修一段也要验证其他动作不变 |
| 验收页面打不开 | 验证最新文件与实际打开结果，同时提供独立动画/图片；排队或策略拦截不算打开成功 |
| 饥荒动作最后需要 SCML 和打包好的文件 | 同版交付 SCML/PNG 与官方编译的游戏动画 ZIP；工程归档不等于游戏包 |

## 3. 返工原因与预防

| 问题 | 修正办法 | 下一次提前检查 |
|---|---|---|
| 只有拆件示意，没有每件可用图片 | 按清单补齐实际透明 PNG | 以文件矩阵定义完成，不以页面数量定义 |
| 原图模板裁片被当作重新绘制 | 改为 image2 参考三视图逐件画 | 保存实际生成图与逐件来源 |
| 单件看似合理，拼起比例、颜色不一致 | 同坐标对照，局部重画与重新配准 | 先做高风险头颈和腿部小样 |
| 接缝、重复毛块、上下颌对不上 | 明确部件边界、重画内衬、调整层级与覆盖 | 拆件计划写清包含/排除范围 |
| 隐藏部件被强行展示造成穿层 | 中性姿势按 `pose_visible` 隐藏，仍保留文件 | 区分“存在”与“可见” |
| 左侧参考容易直接误标为 side | 完整姿势转成原生右侧，再镜像左侧 | 固定方向表，每个动作复查 |
| 死亡姿势悬空、四肢折叠不自然 | 分方向重做倒地和 FK 折叠，校正根部接地 | 完整制作前先验死亡极限姿势 |
| 攻击 IK 超出可达范围 | 降低动作身体高度，保留支撑足目标 | 对全过程测端点误差，不只看静帧 |
| 循环预览末端重复造成停顿 | 导出不重复循环端点，检查连续播放 | 区分闭合关键帧与输出帧 |
| 死亡仍睁眼 | 明确缺少闭眼/失光贴片，未伪称完成 | 状态附件在拆件计划时纳入 |

三只步频不同。总览 GIF 为接续播放做了展示相位归一化，单体文件保留各自节奏；审查精确动作时间应看单体时间线，不以总览蒙太奇代替。

## 4. OpenSpine 实测结论

未确认会导致本工程丢帧或损坏文件的 OpenSpine 缺陷。以下是本次构建的能力边界，不等同于软件崩溃：

| 限制 | 本次处理 | 可提出的改进 |
|---|---|---|
| MCP 预览一次最多 8 张采样图 | 使用原生批量导出适配器 | 提供完整序列/APNG 导出、进度与取消 |
| 整体 JSON 读取上限 512 KiB | `openspine_read_project_chunk` 获取内容和 SHA，再受保护写入 | 改善大项目读取与编辑接口 |
| 无原生 SCML/Klei 导出 | 由原生附件矩阵烘焙 SCML | 提供帧变换导出或 SCML 插件 |
| HTML 导出为 JSON 数据查看页 | 另建本地实际渲染验收页 | 提供动画播放器 |
| 官方 `.spine` 重建依赖已激活官方 CLI | 交付可编辑 JSON 与配图 | 在 UI 中更清晰说明格式与依赖 |

死亡姿势不正确、IK 不可达、接缝缺画属于作者工程或素材问题，不应直接提交成工具 bug。初版构建指纹记录在 `output/openspine/2026-09-06-murk-wolf-C-rig-v1/evidence/openspine-build.json`；不把它称为后续版本的构建。

## 7. 本次工程复现顺序

依赖：JDK 17+、已安装且相容的 OpenSpine 编译产物、Python、Pillow、NumPy、OpenCV、ffmpeg；预览页自动检查还需要 Playwright 及可用浏览器。先核查实际脚本与依赖，不把这些项目脚本当作 OpenSpine 自带命令。

**以下会写入和覆盖生成结果，不要为了阅读流程直接运行。** 普通编辑已有 JSON 不需要从零重建。手改工程先另存工作副本；`build_rigs.py` 会重建动画，`ground_contact.py` 和 `enforce_reach.py` 会改关键帧，`finalize_package.py` 会清理限定中间文件并重写 ZIP。

只在计划从源完整重建、已保留手改版本时，按顺序逐条执行；任一失败就停止：

```powershell
# 先把当前目录切换到单独保存的 <case-root>，再执行以下命令。
$CaseRoot = (Get-Location).Path
$ProjectRoot = Join-Path $CaseRoot "output\openspine\2026-09-06-murk-wolf-C-rig-v1"
Set-Location -LiteralPath $ProjectRoot
python src/build_rigs.py
python src/pipeline.py sample
python src/ground_contact.py
python src/enforce_reach.py
python src/pipeline.py all
python src/export_scml.py
python src/build_review.py
python src/verify_delivery.py
python src/finalize_package.py
```

脚本以自身文件位置计算输出目录；只切换工作目录不会改变输出位置。迁移项目时需检查 `ROOT`、`WORKSPACE`、`SOURCE`、OpenSpine 路径和打包路径。全量重建需要原 V4 目录；日常打开和原生导出交付 JSON 不需要它。
