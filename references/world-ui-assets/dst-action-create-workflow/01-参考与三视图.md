# 01 参考与三视图

目标：先把“画谁、画什么风格、哪些特征不能变”确定下来，为后续拆件提供稳定基准。

## 1. 开工输入

- 个体身份、数量和区别；群体参考不能代替每个个体的设计。
- 最终用途、游戏显示尺寸、观察角度、动作范围和交付格式。
- 用户指定工具与风格；本次明确要求 image2，后来明确保留 C 夸张卡通风。
- 已有 Lua 契约：bank、build、动作名、方向数、循环方式和攻击事件时间。

制作 DST 内容前先阅读当前仓库或团队的开发规则，再按任务选择最少的相关工具说明。使用配套 Codex 技能集时，本流程涉及 `dst-texture-style` 和 `dst-make-scml-animation`；实际生成图片时还应使用当前环境提供的图像生成能力。技能不是本仓库依赖，没有安装这些技能的读者仍可按本文的验收规则使用其他等价工具。

## 2. 搜集参考

1. 搜索实际游戏中的目标生物，优先能看清头部、身体、四肢、尾巴和群体大小关系的图。
2. 保存来源 URL、用途和本地文件对应关系；版权素材只作为设计参考，不宣称自有。
3. 检查文件真实格式。下载名称可能是 PNG/JPG，文件内容却是 WebP，必须解码确认。
4. 身份参考和 DST 动画结构参考分开保存。前者约束外观，后者帮助判断拆件、方向和接地。
5. 新做 DST 风格比对时，按贴图技能选择至少 3 张同类、同尺度原版 PNG；不要强行用原版配色覆盖用户已选定的设计。

三狼案例的公开网页来源列在 [案例复盘](05-三狼案例与返工复盘.md) 中；案例归档内另有 `output/imagegen/2026-09-05-murk-wolf-review/README.md` 保存素材与本地文件的对应关系，该归档未随本仓库分发。本次流程整理没有重新进行网页搜索。

## 3. 多版风格与独立三视图

1. 用相同个体、相近姿势和尺度制作若干风格候选，让用户比较风格而不是比较构图。
2. 每个个体分别制作正面、侧面、背面；保持头身比、肩高、地面线、标记和配色一致。
3. 双头个体保持两套头部身份，不合并为单头；两个小个体不复用同一张图冒充区别。
4. 每版附实际图片，标清候选编号和个体名，提交用户选定。
5. 选定后记录原图路径与 SHA-256，后续生成始终引用这一版本。

本次保留的美术方向是 `front / left / back`，其中 `left` 是朝左的侧视图。这是素材方向，不是最终 DST 原生 `side` 约定。

## 4. G1 验收

- 三个视角看起来属于同一个个体，主要比例、特征和颜色能对应。
- 每个个体都有自己的文件，群体大小关系另外检查。
- 大狼双头、两只小狼的差异被保留。
- 用户明确选择风格和基准版本；未确认的变体不进入批量拆件。
- 图片能直接打开检查；不能只交文字风格描述。

需要返工时只修改有问题的个体或视角，修订版本号并再次审查，不悄悄覆盖已确认的基准。

## 5. 选定后的文件管理

本次用户要求删除其他风格，因此清理范围是未选中的风格图片、专用提示和混合风格交付包。不能误删“小狼 A”和“小狼 B”，它们是保留风格下的个体。

删除前列出具体文件，核实绝对路径和用户授权范围。保留 C 三视图、原始参考、相关提示词和校验记录。本次流程整理不再次执行清理。

## 6. 可复用提示词

以下是新任务模板，不是本次生成记录的逐字转录：

```text
基于附件参考，为【个体 ID】制作独立的正面、左侧面、背面三视图。
风格：【已指定风格；未选定时填写候选风格】。
三个视角必须保持同一身份、头身比例、毛色分区、标记与材质。
必须保留：【头部数量、面部差异、耳形、尾形等】。
三个视角统一比例与地面线，完整显示轮廓，彼此不遮挡。
只画该个体，不把不同个体合并到同一角色，也不加入场景或解释性文字。
本轮只确定设计，不把整张三视图声称为已经可用于骨骼动画的部件。
```

交付：参考记录、候选实图、选定的独立三视图、提示词、生成模型记录、版本和用户确认状态。
