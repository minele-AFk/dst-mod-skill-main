# 饥荒动作制作流程

整理日期：2026-09-06；交付要求与执行检查更新：2026-09-07；30 FPS 与可移植复现补充：2026-10-22。依据：《英雄联盟》三狼 C 风格制作案例、素材交付说明、OpenSpine 工程与验证记录。

这套流程用于把角色参考转成可编辑、可验收、可编译交付的《饥荒联机版》骨骼动画。它不是“生成一张图后直接导入游戏”，也不是已经完成游戏接入的声明。

**最终交付必须同时有 SCML 源工程及全部引用 PNG，以及用官方 Mod Tools 实际编译完成的饥荒动画包 `anim/*.zip`。** OpenSpine JSON、网页、GIF/MP4、PNG 帧序列和普通工程压缩包都不能替代这两项。除用户明确只要求某个中间阶段外，不能把“预览已做好、以后再编译”当作整套动作制作完成。

## 使用范围与路径约定

本仓库是可独立阅读的流程文档，不包含 OpenSpine、官方 Mod Tools、游戏文件、个人 Codex 配置或三狼案例的大型素材与构建产物。克隆仓库后可直接阅读 Markdown；只有实际制作、编译或游戏验证时才需要另行安装相应工具。

- 文档间链接均相对于本仓库根目录，不依赖克隆位置。
- `assets/`、`src/`、`delivery/`、`review/` 等示例路径均相对于正在制作的动画项目根目录，不是本流程文档仓库的固定目录。
- 第三方工具路径通过环境变量或项目本地配置提供。本文统一使用 `DST_GAME_HOME`、`OPENSPINE_HOME`、`DST_MOD_TOOLS_HOME` 和 `DST_SCML_ANALYZER`；不要把个人用户名、盘符或 Steam 库位置提交到仓库。
- [三狼案例与返工复盘](05-三狼案例与返工复盘.md) 中的证据路径相对于单独保存的案例归档根目录。该归档未随本仓库分发，因此这些路径用于说明归档结构，不是本仓库内的可点击资源。

## 一、流程总览

```text
确定个体、用途和运行时要求
  -> 搜集参考，用选定的图像生成/编辑工具制作多版风格
  -> 用户选定风格，每个个体独立三视图
  -> 先列部件清单、归属、关节和遮挡
  -> 代表性部件小样，在 OpenSpine 制作单个体短动作
  -> P0 技术小样：SCML 导出对照、官方编译、隔离游戏加载
  -> 图像工具参考已确认三视图，逐个部件生成
  -> 导出全部独立透明 PNG，登记装配位置
  -> 用实际 PNG 拼合，与三视图对照并修正
  -> OpenSpine 建骨架、绑定、验证极限姿势
  -> 按代码契约完成四方向动作，检查腿部约束与状态衔接
  -> 原生渲染、逐帧检查、交付用户视觉验收
  -> 补齐运行时动作与命名，导出 SCML + 全部 PNG 并对照原生画面
  -> 官方 Mod Tools 编译，核对实际二进制与纹理产物
  -> 同版交付 SCML 源文件 + 编译好的 anim/*.zip + 构建/校验记录
  -> 按已确认范围接入游戏，完成游戏内和联机验证
```

后续项目应把运行时调查提前到开工阶段；本次是在进入 OpenSpine 制作时详细核对的。这是对实际经历的流程改进，不是改写历史。

P0 是新增的批量制作前技术门槛，执行方法见 04 第 0 节。先用少量代表性素材跑通完整链路，再扩展全部个体和动作；小样成功不代表全量 G6/G7 通过。若本轮明确只做中间阶段，不擅自启动编译或游戏，记录 P0 未完成及未验证风险；只有用户明确允许按中间阶段范围继续时才继续，不把豁免写成通过。

## 帧率与时间基准

自 2026-09-18 起，新制作统一按 30 FPS 组织：OpenSpine 母版、关键帧时间基准、原生采样、预览播放和最终编译动画都以 30 Hz 为目标。F0 为零时刻，`t = F / 30` 秒；SCML 的整数毫秒按 `round(F × 1000 / 30)` 从绝对帧号换算，不累计固定 33 ms。

某些已测官方编译器固定输出 40 FPS；这描述已测版本，不推断所有版本。P0 必须实测当前工具链实际产物，并从最终 `anim.bin` 逐动作读取 FPS、帧数、时长和事件。若工具输出 40 FPS，不能把最终要求改成 40 FPS，也不能只改预览速度或二进制标签；必须通过经过验证的适配链保留姿势、时长、事件和循环边界，否则标记为“30 FPS 编译未通过，阶段交付”。

## 三、阶段门槛

| 阶段 | 必须交付 | 进入下一阶段的条件 |
|---|---|---|
| G0 需求 | 个体表、动作表、方向、交付格式、代码契约 | 范围清楚，缺项和未知项有记录 |
| G1 设计 | 风格候选、每只独立三视图 | 用户明确选定版本，不靠推测 |
| G2 部件方案 | 部件清单、父子关系、接缝、显隐、命名 | 可覆盖预定动作；需用户审查时先提交 |
| P0 技术小样 | 单个体短动作、SCML/PNG、真实编译样包、导出对照和隔离加载记录 | 代表性功能、命令和加载验证通过；未执行部分如实记录，不默认放行批量制作 |
| G3 全部拆件 | 每件实际 PNG、来源、位置与完整性报告 | 无漏件，并能逐件打开审查 |
| G4 静态装配 | 实际拼合图、原图对照、修正记录 | 比例、颜色、层级和连接可接受 |
| G5 骨骼与动作 | 可编辑骨架、四向动作、逐帧预览 | 腿部专项和修改范围回归通过，视觉问题修正后交用户验收；仅属阶段验收 |
| G6 源文件与编译包 | 同版本 SCML、全部引用 PNG、实际编译的 `anim/*.zip`、构建日志、哈希清单 | 源文件检查、原生与 SCML 对照及官方编译成功，包内契约和依赖核对完成，编译后画面对照状态已记录 |
| G7 游戏接入 | 资源声明、运行时接法、游戏验证记录 | 按确认范围接入，游戏内方向、事件、状态衔接和联机实测通过 |

每个门槛分别记录“技术检查结果”和“用户审查结果”。用户要求继续制作，可以继续推进，但不能据此把前一版本写成已验收。

G6 是最终资产交付的必经阶段，不是可选附件。G6 通过不代表 G7 通过；未运行游戏时必须写明“已编译，未游戏验证”，编译未完成则写“阶段预览/源工程，最终交付未完成”。

## 四、不可省略的规则

1. 三只生物是三个独立个体；风格 A/B 与“小狼 A/B”不是同一概念。
2. 先决定拆哪些部件，再用选定的图像生成/编辑工具逐件画。拆分示意板不能代替独立 PNG。
3. 已确认三视图是身份和风格基准。需要补画隐藏面，不能擅自换脸、换比例或换风格。
4. 拼合图必须由交付 PNG 实际装配生成；不能拿完整原图充当拼合结果。
5. 静态接缝通过不等于大幅运动通过；临时关节标记不等于已验证的骨架。
6. 动画必须有真实骨骼、父子继承和关键帧；本流程采用 OpenSpine 原生求解与渲染。
7. 本项目 `side` 原生朝右，左面整体镜像；四向预览固定 `left, right, down, up`。
8. 文件数量、自动测试、主观美术验收和游戏验收分别报告，不能互相替代。
9. 只清理用户明确要求删除的风格和本任务明确的中间产物；保留选定设计、原始生成图和可编辑工程。
10. SCML、部件图、编译包和验收媒体必须对应同一修订版。修改源工程后重导出、重编译和重校验，不混交旧二进制。
11. 普通交付归档 ZIP 与饥荒运行时动画 ZIP 分别命名、检查和报告；给 PNG/JSON 改扩展名或直接压缩不等于编译。
12. 新工具链先做 P0。只存在工具目录或示例参数，不等于已有经过实测的编译命令。
13. 约束必须通过实际姿势证明生效；XML 检查不能代替导出画面对照，单段预览不能代替游戏状态衔接测试。
14. 局部返工先冻结基准和允许修改范围，复查其他个体、方向、动作及共用骨骼，不能只展示修好的片段。
15. 动画包内的 Build 不等于游戏实际使用的 Build；G7 必须用最终 `anim.bin` 与运行时实际选中的 `build.bin`/TEX 组合验证。
