# DST 贴图风格

目标是匹配用户选定参考的画法，并在资产实际显示尺寸保持清晰。手绘不等于粗糙、脏旧或抖线；精致不等于密纹、厚描边或写实渲染。先遵守 [开发边界](../../development-contract.md)。

## 先选参考，再写提示

优先级：本次明确要求与参考 → 已确认的同系列成品 → 库内相近样本 → 风格文字。不要让固定示例覆盖用户最新参考。多个参考有冲突时，说明差异并请用户选主参考；已有明确选择则直接沿用。

| 任务 | 读取与使用 |
|---|---|
| 有用户例图、要优化画风或匹配 Mod | 先读 [参考驱动提示流程](references/reference-led-prompts.md)，再按 [Mod 参考索引](references/mod-clean-style.md) 选择相符样本；Mod 没有统一画风 |
| 明确要求原版 DST | 读 [原版画法](references/texture-style.md) 和 [原版目录](assets/vanilla/CATALOG.md)，选同职责样本 |
| 只有“手绘”“精致”，缺少基准 | 检查会话已确认的方向；仍有歧义时给少量有图的风格选项，不擅自改成粗糙原版或厚重奇幻 |
| 人物立绘、人物拆件 | 同样使用参考驱动流程，但另需人物比例、面部、服装和方向参考；接入 [人物拆件](../dst-character-parts/GUIDE.md)，不拿武器当完整人物画风标准 |

新入库的 [2026-10-15 用户参考](assets/user-reference-20261015/CATALOG.md) 展示细线蓝白刃、银白青蓝法器、金框蓝珠、紫黑镰形武器。它们是不同资产的画法证据，不是要求每件新物品都使用同样题材、配色或装饰。

## 工作顺序

1. **确认职责和范围**：库存图标、世界物体、手持 symbol、人物部件、建筑、UI 或 FX；记录目标尺寸、视角、用途。区分只改贴图与完整游戏资源。
2. **判断保留还是重设**：用户满意原造型则锁定轮廓、比例、部件和配色关系，只优化指定画法。明确不满意则先确定新方向；已选方案不重复询问。
3. **打开并标注参考**：通常一张主画风参考，按需增加结构或材质参考，并为每张指定唯一用途。不要按“至少三张”凑数，不把不同画法平均混合。库内资源可用，外部资料/其他 Mod 仍须用户授权。
4. **写简短制作卡**：按 [参考驱动提示流程](references/reference-led-prompts.md) 记录结构、不变量、线条、明暗材质、细节层级和目标尺寸；不把整篇技能文档塞进提示词。
5. **生成或有界修改**：用户要求生成/编辑位图时用 `$imagegen`，实际传入已查看的参考图，并在提示中说明顺序与职责。严格按工具当前接口调用；不假设存在名为 `image_edit` 的工具。选定结果只修本轮问题。
6. **后处理**：在本专题目录运行 `python tools/process_texture.py <src> --name <id> --out <独立目录> --review`。默认保留输入颜色和透明度，输出 master、256 和 64；已有 RGBA 不抠底。只有确认存在纯色底才显式用 `--key-background`。不要用自动擦角代替人工检查。
7. **分开验收结构、画风和缩略表现**：与主参考并排比较线重、材质画法、焦点与细节密度；检查 256 与 64 原尺寸，以及浅/深/棋盘背景。放大图只辅助找问题，不能代替 64 原尺寸检查。
8. **按授权交付与入库**：原始文件不覆盖；一次一个物品，待用户确认才入库和继续下一件。已获清理授权时，在核对成品、参考、提示词及文件校验信息后清理本轮中间产物。用户要求等待则停止推进。

## 图像质量与尺寸

- 结构线解释连接、前后遮挡、厚薄和材质。手绘感可来自流畅的收笔、轻重与形体概括，不必叠噪点、划痕、破边。
- 从参考分别提取线、面、色和材质；硬边分面、细腻局部渐变、尖锐高光都可成立，是否采用以选定参考为准。
- 原图已糊或像素不足时，明确哪些细节看不清；不虚构纹样或通过放大假装获得新信息。
- 若 256 清楚、64 糊，先查细节尺度、线重、背景残留和缩放透明度；不要直接往母版加纹样。
- `--content-ratio` / `--icon-ratio` 是 **alpha 边界框面积 / 画布面积**，不是主体高度比例。细长物体可能先受长边限制，不能强行填满面积；改变画布占比不会修正刃柄比例。
- 256 是交付画布，不等于游戏世界大小。world/swap 还需检查 symbol 尺寸、pivot、动画与实际显示，见 [展示大小](assets/vanilla/DISPLAY_SIZE.md)。人物部件保留装配画布/pivot，不套用物品居中裁切。
- 分析工具 `tools/analyze_textures.py <reference.png> --summary-only` 可检查尺寸、透明度和边界；统计数值不能证明风格相似。

## 意图与交付

| 用户意图 | 交付 |
|---|---|
| 概念图 / 设计方案 | 按约定出设计图；不自动转换或接入游戏 |
| 转贴图 / 优化画风 | 保留已确认设计，按参考重画透明 PNG；显示 256 和 64 效果 |
| 精确修改 | 列出本轮修改点与保留项，只改指定内容 |
| 参考画风 | 迁移画法，造型依用户设计；不照搬示例配饰 |
| 参考设计 | 采用被指定的结构特征，画法独立确定 |
| 完整游戏资源 | 贴图、图集、动画、代码注册及验证，按下面清单；当前只是贴图会话时，不因“做一把武器”擅自扩展到代码 |

完整武器/物品资源：背包图标、地面图、手持 swap 图；`.xml` + `.tex`；idle 与 swap 的编译动画；所需 prefab、装备逻辑、特效与注册。先明确需求和属性，再读对应开发专题，不以一张 PNG 宣称游戏可用。

动画按关节、遮挡变化和独立运动拆件；留足遮盖区，检查描边、pivot、镜像、接缝及方向一致性，与 [SCML 动画](../dst-make-scml-animation/GUIDE.md) 协同。FX、阴影的半透明例外见 [原版参考](references/texture-style.md) 对应章节。

交付说明应区分：设计/画风检查、透明度与尺寸检查、动画装配验证、实机验证；未执行的不能宣称通过。维护技能不自动授权生图测试；提示改进需要后续用户实际生图和反馈验证。
