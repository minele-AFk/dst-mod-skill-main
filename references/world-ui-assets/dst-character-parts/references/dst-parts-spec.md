## 1. 模板优先级

优先级从高到低：

1. 用户指定人物当前实际编译使用的SCML。
2. 同一人物最近一次可正常编译的源工程。
3. 身材与服装结构最接近的DST人物模板。
4. 通用Wilson骨架。

文件夹名称不是可靠的语义标准。必须读取SCML确认folder、file、尺寸、pivot和动画引用；同名部件在不同人物中可能承担不同层级。

## 2. 常见部件族

| 部件族 | 常见名称示例 | 拆分要求 |
| --- | --- | --- |
| 头部 | `headbase`、帽子版头部 | 不烘焙头发和表情；保留脖颈连接区 |
| 五官 | `eyes`、`mouth`、`cheeks`、`beard` | 表情帧单独输出；位置服从头部pivot |
| 头发 | `hair`、`hair_hat`、前发、后发 | 前后层分开；帽子遮挡版不能只粗暴裁掉顶部 |
| 躯干 | `torso`、`torso_pelvis` | 腰线稳定；不要合并裙摆、手臂或项链摆件 |
| 手臂 | `arm_upper`、`arm_lower`、袖口 | 每段补全关节内侧，旋转后不露透明洞 |
| 手 | `hand` | 手腕处留重叠，握持姿势按模板帧分别制作 |
| 下肢 | `leg`、`foot` | 裙装角色仍需保留被裙摆遮住的必要腿部 |
| 服装摆片 | `skirt`、coat、cape等项目自定义名 | 依动画层级拆前后层；避免与长发烘焙 |
| 饰品 | bow、brooch、earring等项目自定义名 | 会摆动或跨越多个身体层级的饰品必须独立 |

## 3. 复杂服装与长发

- 先把角色理解为“骨架层、身体层、衣服层、头发层、饰品层”，再决定图像切口。
- 长发至少保留一个身体后层；覆盖肩膀或胸前的发束另做前层。
- 蓬裙优先拆成腰部连接、前裙摆和后裙摆。若模板只有一个裙摆symbol，也要确保腿部与裙摆能独立遮挡。
- 蝴蝶结、长缎带、披风和垂坠链条只要需要摆动，就不要画死在躯干上。
- 被遮挡区域按相邻线条走势补全，避免生成新的花纹、扣子或褶皱。

## 4. 方向与镜像

- 分别核对正面、背面、侧面，不以简单旋转代替换面绘制。
- DST常以一套侧面素材镜像左右方向。若发卡、单肩披风、眼罩、徽章或武器鞘只在一侧，镜像后会换边；必须提前和用户确认这是可接受的游戏化处理，或采用独立方向Build/运行时覆盖。
- 朝上视图应显示后脑与背部主要结构；朝下视图应保留脸部和胸前结构。不要让两者仅靠五官显隐区分。
- 三个视图的脚底线、头顶高度和头身比应一致。侧面头部不能因透视被纵向压扁。

## 5. 透明边缘

- 使用直Alpha透明PNG，背景Alpha必须为0。
- 删除白色底、棋盘格和生成模型留下的低透明度脏像素。
- 描边自身可以半透明，但不允许出现来自背景的白色或灰色毛边。
- 在透明背景、浅色底和深色底上各检查一次边缘。
- DST纹理压缩会放大暗色半透明网格与脏边；必要时清理RGB泄漏，并在源PNG四周保留足够透明留白。

## 6. 验收清单

- 所有SCML引用的PNG存在，路径大小写完全一致且尺寸匹配。
- 所有拆件有Alpha通道且可见像素非空。
- 关节旋转时无断层、透明洞和重复轮廓。
- 头发、手臂、躯干、裙摆交叉时层级正确。
- 帽子、手持物、背包和幽灵状态不破坏人物Build。
- 左右镜像没有产生不可接受的设定错误。
- 重组后的头身比、裙长、头宽和侧面头高符合最终设定图。
- 正式编译包经过游戏内 `idle/run/attack/hit/death` 实测。
