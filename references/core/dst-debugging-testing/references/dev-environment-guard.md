# 开发调试功能的启用边界

调试入口只在项目明确的开发配置下注册，发布默认关闭。文件夹名、显示昵称与账号 ID 都不是服务器权限验证，也不能由它们自动授权执行命令。

## 明确配置

```lua
-- modmain；对应 modinfo 中定义默认 false 的 dev_mode 布尔配置。
local dev_mode = GetModConfigData("dev_mode") == true
if dev_mode then
    -- 只加载本项目实际提供的开发注册文件。
    modimport("scripts/my_mod/dev.lua")
end
```

开发文件的存在与内容先确认；不能复制示例后假设路径已经有文件。modimport 在模组环境每次执行，不是缓存模块。

## 环境与身份

modname 是当前模组环境身份，可用于区分明确约定的本地目录，但目录名和 Workshop ID 的模式不保证所有环境通用。显示昵称可变，不用于权限。

需要本地身份辅助诊断时按当前 TheNet:GetLocalUserID 等实际接口读取，前端/离线可能缺值；不要使用未查证的 TheSim:GetUsersName，也不把单机与 DST API 混列成默认兼容方案。日志与交付中不暴露身份令牌或私人路径细节。

## 防止调试改变正常逻辑

- 无开发配置时不创建热键、调试 Widget、周期扫描或危险命令。
- 关闭功能时撤销其 handler、任务与监听，重复启用不叠加。
- 服务器业务的请求校验仍在业务层；客户端自报 dev_mode 不授予权限。
- 不用 pcall 吞掉调试脚本失败后声称通过；记录第一条错误与实际执行端。

发布前比较候选目录与声明，剔除本次测试存档/令牌/日志，保留必要运行资源；不能为了“清理”删除用户原文件。实机验收与调试日志证明分开。
