# DST Mod 解密案例与保护形态

本页从用户明确授权的 Mod 笔记中提炼可复用经验。它只用于定位相似保护和选择验证路径，不授权读取任何 Workshop 内容，也不能把某个目标的算法、常量、映射或运行时结果当成另一个目标的结论。

先核对目标 ID、版本或更新时间、入口文件和哈希，再读对应笔记原文。案例记录的是当时快照；同一 Mod 更新后，层级、保护范围和明文文件都可能变化。

## 可复用的保护形态

这些名称只用于识别相似结构，不能仅凭字符串或外形选算法：

| 形态 | 应优先检查 | 常见误区 |
|---|---|---|
| 扁平化入口 | 常量池、分派块、条件分支、读取边界 | 把单行压缩、控制流或数字运算当作载荷加密 |
| 自定义 Base64 | 目标字母表、填充、整数拼接、层级 | 复用另一 Mod 的标准 Base64 或旧字母表 |
| 自定义 VM | 序列化标签、操作码、常量池、子原型、造表指令 | 只看到 VM 或反汇编就声称已得源码 |
| 单字节置换与逆序 | 255 项双射、字节 0 的处理、变换顺序、反向重建 | 用几个短词猜表，忽略整文件逆序 |
| 流密码与哈希容器 | magic、版本、种子、计数器、哈希覆盖范围 | 按猜测密钥解出一个可读前缀就宣称完整 |
| 入口加子脚本双路径 | 主逻辑入口、require/modimport shim、按需加载 | 只恢复入口文件，漏掉 scripts 和其他入口 |
| 运行时字符串混淆 | 字符串产生位置、字符编码、还原边界 | 把字符替换后的文本当原始中文 |
| 保护范围不统一 | 明文清单、文件角色、入口与 scripts 差异 | 假设所有 Lua 使用同一保护 |

## 恢复路线的选择

先选静态路径：

1. 从明文入口还原变换链和目标参数。
2. 对纯解码函数做静态提取；只在已授权的隔离环境执行最小函数。
3. 从载荷变换得到明文，并以逆变换逐字节核对。

只有静态路径确实需要观察动态边界，且用户授权该动作时，才考虑运行入口或 VM。隔离运行必须说明捕获点、模拟的环境值、反调试路径和实际取得的层级；捕获到中间层、loader 或 VM 容器仍不算业务源码。

道诡异仙案例的 `loadstring` 捕获、珂朵莉的纯解码器执行，以及“不执行入口、只静态解释状态机以抵达解包边界”的做法，是三条不同路线。它们都依赖当前目标的授权和证据链，不能互相替代，也不能把某一条写成所有 Mod 的固定流程。

## 失败与纠正

| 症状 | 可能的实际原因 | 下一步 |
|---|---|---|
| 解出高熵乱码 | 字母表错误、层级混合、填充或逆序顺序错误 | 回到目标入口重新提取每一层参数 |
| 只有局部短词合理 | 映射只覆盖部分字节、索引偏移错误或用了旧表 | 检查完整双射、字节边界和逆序后的上下文 |
| 解密后脚本全部语法失败 | 错表或错误裁切，也可能是 Lua 版本不符 | 分开检查映射、字节保留与语法器版本 |
| 只得到包装器 | 还没进入嵌套原型、VM 解码器或后续载荷 | 继续定位实际 `load`/`loadfile`/require 边界 |
| 重跑覆盖失败 | 副本继承只读属性、目标被占用 | 换独立候选目录，不改原 Workshop 文件 |
| 只核对了几个文件 | 未遍历原清单，或只对 Lua 建了哈希 | 补全所有受保护载荷与全部交付资源 |
| 只做了 Lua 5.4 语法检查 | 实际 DST/Lua 5.1 语法未验证 | 如实标记版本，补做对应编译或运行验证 |
| VM 难以逆向 | 保护强度高、样本缺关键入口或动态密钥在 VM 内 | 明确卡住层级，保留资源/架构成果；不要伪造源码 |

历史笔记中“不可读”“不可恢复”“无法解出”等结论只描述当时的证据和投入边界。新版目标应重新检查，同时也不应因为旧失败就承诺一定可恢复。

## 验收清单

- 原件只读，建立可追溯的文件清单与哈希；
- 明文、入口、中间层、受保护载荷、资源分别识别；
- 每层算法和目标参数来自当前快照，不跨 Mod 复用；
- 完整映射经短明文交叉检查，并以目标 VM/算法结果为准；
- 所有受保护载荷可逆回原密文，最好有独立实现比较；
- 交付目录保留原相对路径，Lua 与资源总数符合原清单；
- 记录实际使用的 Lua 版本、工具版本、命令和退出状态；
- 恢复完整性、语法检查、运行时加载、游戏行为分别报告。

最后一层验收是游戏运行；静态恢复成功不等于角色、技能、UI、联机、存档和重启加载均正常。
