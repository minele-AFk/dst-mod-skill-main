# 开发边界、源码版本与验证约定

主入口和内部专题共用本约定；用户本次指令与工作区 AGENTS.md 优先。内部专题是按需文档，不自动授予读取第三方材料、修改游戏或启动服务器的权限。

## 修改与参考范围

- 询问、评价、解释请求只读；用户要求修改后，先理解当前内容，在指定范围内实施并说明改动。已授权的修复不重复询问是否要修。
- 不改无关文件，保留用户已有改动；Git 提交、推送和打 tag 必须另有明确授权。skill 内容变更默认同步更新 `VERSION` 与维护记录，发布时使用同版本 `vX.Y.Z` tag；用户明确要求本次暂缓版本号时按当次授权执行。提交、推送或 tag 的范围由当次授权决定。
- 大型项目先明确范围、方案、结构和估算，再按用户确认实施；小型修复按已明确的需求执行。
- 不确定 API、机制、组件、物品代码名或实现方式时查证，不确定需求时询问。简单机械编辑和已明确且不依赖专业知识的修改不强制检索知识库。用户未授权自行选择时，影响功能或行为的方案取舍交给用户。
- 引用物品前查 [物品名字.txt](prefabs/物品名字.txt)，再核对目标版本中的 prefab；表里缺失时如实说明，不猜代码名。

本工作区的路径边界：

| 路径或材料 | 读取条件 | 修改条件 |
|---|---|---|
| 用户指定的本地 Mod | 当前任务涉及的文件 | 用户已要求相应修改 |
| `D:\mods\scripts` | 开发 Mod、核对官方实现时可读 | 用户明确要求，否则只读 |
| 当前安装游戏的 `data/databundles/scripts.zip` | 核对官方实现或版本时可读 | 只读，除非用户明确要求修改 |
| `D:\mods\资料包` | 用户明确点名该资料 | 用户明确要求，否则只读 |
| `steamapps/workshop/content/322330` 及其他第三方 Mod | 用户明确要求参考、讲解或学习指定 Mod | 用户明确要求，否则只读 |
| `references/mod-notes/` 的第三方分析笔记 | 用户明确要求参考对应 Mod 或这些笔记 | 仅在用户明确要求维护笔记时修改 |

错误堆栈出现 Workshop 路径、专题文档含第三方链接、目录已经挂载，都不等于读取授权。未授权时不列目录、不搜索、不打开第三方 Mod 或笔记；可继续分析用户提供的日志及已授权目标代码。

用户指定仓库融合的公开工程知识包位于 `references/knowledge/dst-engineering-kb`，可按任务检索其中已融合的记录；许可不扩展到记录所指向的外部 Mod 或私人源码。知识包保持只读，模式/事实/更正/未运行测试分别判断，重要结论仍核对当前目标源码。

## 源码入口与版本

1. 显式指定的源码路径优先；工具也可用 `DST_SCRIPTS_DIR` 指定解包目录。
2. 未指定时，本工作区可优先定位 `D:\mods\scripts`，再定位已知游戏目录的 `data/scripts` 或 `scripts`。只探测这些候选，不递归搜整盘。
3. 解包目录应直接包含 `main.lua`、`modutil.lua`、`entityscript.lua` 和 `components/`；部分工具也接受其父目录，具体见工具帮助。
4. 找不到内容、怀疑版本差异或结论影响联机/存档时，核对当前安装的 `data/databundles/scripts.zip`，使用 `dst_zip_tool.py` 定点读取，无需解包覆盖本地源码。
5. `D:\mods\scripts` 为手动维护快照，不保证最新；安装包也只代表本机安装版本。记录源码来源、研究日期与可取得的版本/文件指纹，不能宣称等同于线上最新版本。

## 检查结果如何解释

- API 检查器仅查部分直接调用的源码声明，主组件与 Replica 分开检查；参数签名、执行端、生命周期、引擎绑定及动态注入仍需源码追踪或运行验证。
- 新增 AST 工具位于 `references/tools/engineering/scripts/check_api.py`，支持整个 Mod 的 Lua 语法及自定义组件声明核对；它的 `1` 为语法错误、`2` 为待核对/输入或依赖问题，不与下方原有快速扫描器的退出码混用。
- `check_api.py` 退出码：`0` 为直接声明匹配，`1` 为未找到对应端的方法声明，`2` 为输入/源码错误，`3` 为需要人工核对。不存在的输入、空目录和零调用不能报告通过。
- 工具报告的别名、计算索引、动态字段和未知实体方法逐项核对；不得通过删掉检查目标或吞掉告警获取绿色结果。
- 报告区分已执行检查、静态结论、推断、未覆盖和待游戏验证。工具成功退出不代表游戏行为正确。
- `run.ps1 check_api_fast` 与 `check_api_ast` 分别调用以上两种检查器，保持各自退出码；`zip_read` 默认无缓存，原有源码工具仍兼容。命令与参数见 [工具台账](tools/README.md#明确的命令入口)。
- skill 维护扫描在进入目录前排除第三方笔记、冻结知识包、Git、缓存及目录联接；这些跳过项不属于“检查通过”的覆盖范围。维护检查不会运行其中的工具。
- 专服启动、测试桥安装、Lua 注入和存档操作只作用于已授权的独立测试环境；平台未适配时报告限制，不尝试在真实存档中补救。
