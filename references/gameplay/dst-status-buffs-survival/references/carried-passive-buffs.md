# 携带被动能力与恒温照明：背包、持有者和效果生命周期

> 源码复核：2026-10-18，本机 `scripts.zip`。这是实现合同，不是已实机验收的完整 Mod。

适用于容器内有指定物品时获得温度效果、投喂后提供随身照明等能力。物品代码名先查 [名称表](../../../prefabs/物品名字.txt)，本页用项目配置传入匹配条件，不猜原版名称或标签。

## 一、先定义生效条件与归属

- 输入包括容器、内容匹配函数、真正持有者、昼夜/洞穴条件以及配置数值。
- `inventoryitem:GetGrandOwner()` 可得到最外层持有者，但结果也可能不是玩家；检查实体有效性、所需组件、存活/幽灵条件。
- 子容器是否计入、套娃循环如何排除、转交/丢地时是否立即失效，应先由设计决定。不要无界递归所有物品引用。
- 容器内容变化、装备/卸下、持有者改变、昼夜和移除触发统一 Reconcile；用低频复核弥补事件遗漏时，保留任务句柄并在不需要时取消。周期轮询不天然优于事件。
- Reconcile 必须可重复执行：相同输入不重复创建 FX、不重复叠加 modifier、不重复注册监听。

## 二、温度 API 的真实区别

本机 `components/temperature.lua`：

| 调用 | 实际效果 |
|---|---|
| `SetTemperature(value)` | 当次直接 clamp 并更新 current，发送冻结/过热边界与 temperaturedelta；不是渐变接口 |
| `SetTemp(value)` | 写入持续控制字段 settemp，并立即调用 SetTemperature |
| `SetTemp(nil)` | 清除持续控制字段，恢复常规更新路径；不是恢复某个旧 current |

周期调用 SetTemperature 只能形成定期校正，两个周期之间仍可能受环境影响。SetTemp 会影响后续温度更新，撤销时若遗漏清理，效果可能在物品离开后继续存在。

SetTemp 是共享单值，不是按来源管理的 modifier。两个物品或 Mod 同时改它时，“保存旧值→离开时恢复”可能覆盖后来产生的效果。需要真正恒温时，为项目建立以来源为键的温度控制协调器，统一优先级与移除规则；不能仅凭当前数值相等就认定该字段仍归自己所有。保温能力可优先评估原版隔热/热源机制，但隔热不等于固定体温。

验收必须包含：获得效果、内容取出、整包转交、死亡/重生、存读档，以及另一个温度控制者同时存在。45 度之类常量是设计值，不能由例子推导成免疫所有温度机制。

## 三、随身照明的状态与表现

投喂累计值属于服务端业务组件：校验材料、上限与消耗，保存原始等级/累计值，再派生半径。昼夜只决定是否开启，不要在每次昼夜切换再次累加。

Light 是 `entity:AddLight()` 创建的引擎对象，没有原版 `components/light.lua`。光源 Prefab 必须由项目提供，并明确资源、Network、FX 标签、persists 与清理行为，不能直接 SpawnPrefab 一个未定义的名字。

| 层次 | 职责 |
|---|---|
| 服务端 | 确定携带条件、等级与是否生效，执行玩法权威逻辑 |
| 同步 | 按同类原版光源选择网络实体/状态字段；普通 Lua 半径不会自动复制 |
| 有画面的客户端与房主 | 首次初始化和 dirty 时应用 Light；房主也需要初次刷新 |
| 专服 | 不运行纯本地图形初始化；游戏逻辑仍按合同执行 |

父子关系的选择会影响空间位置：物品进入 inventory/INLIMBO 后，不能假定挂在该物品上的 FX 仍正确显示在玩家身上。明确跟随持有者或物品的场景；转交时解绑旧父实体，按所选 Prefab 合同处理 Transform/Follower。临时 FX 可不入档，恢复时由已保存的业务状态重建。

## 四、清理与休眠

集中记录当前持有者、内容/世界监听、周期任务、modifier 来源以及 FX 引用。持有者变更先清理旧对象，再附加新对象；取消监听时保留原函数与 source。移除路径要幂等，缺失/失效对象允许安全跳过。

`entitysleep/entitywake` 是实体的模拟休眠状态，不能等同于玩家上床睡觉。只有当能力语义允许暂停时才据此停任务；玩家的睡眠行为另查 sleeper/状态机。也不能把父实体移除视为所有外部监听和跨实体任务都会自动清理的保证。

## 背包交给别人后，原玩家仍恒温

先分开检查当前背包归属、旧玩家上的持续控制字段、以及仍在旧对象上执行的任务/监听。转交时只更新新玩家不会自动撤销旧效果。通过统一的来源协调器释放旧来源，再绑定新持有者；若共享字段已经被别人接管，不盲目 SetTemp(nil) 覆盖其控制。温度效果是否仍存在，要看当前状态与调用链，不能单凭背包已离开推断。
