# 设计案例：武器、升级与主动技能

保留基础攻击、升级、冷却、主动技能和投射物五部分，分别接入已有组件与动作链；不把依赖项目私有升级组件和未提供资产的片段称为可直接运行成品。

## 最小拆分

| 层 | 责任 |
|---|---|
| 物品 Prefab | 公共动画/标签/网络、主机武器/耐久/装备组件 |
| 升级组件 | 保存等级与投入事实，验证材料、数量和上限 |
| 伤害读取 | 由基础参数与等级重算，不重复乘当前 damage |
| 主动技能 | 服务端校验拥有者、解锁、目标、距离、资源与冷却 |
| Action/SG | 客户端发现/预览、服务端执行帧及取消 |
| 投射物 | 发射者/武器归属、命中/错过/移除和单次结算 |
| Replica/UI | 显示已复制等级与冷却，不决定最终可用性 |

## 升级合同

投入前检查材料与等级，消费单件或指定数量，失败不删整叠。变更等级后统一重算派生伤害、上限和说明；读档也走同一幂等公式。

保存等级/必要配置版本，不保存任务或当前攻击目标。改变平衡、最高等级或材料规则时明确旧物品如何迁移。分开的武器实例不能共享一个全局“当前等级”。

## 伤害与技能

已有 weapon/projectile 能结算时不另加 health:DoDelta。普通与位面伤害、防御和击杀归属沿 combat；Projectile:Hit 已可能攻击，onhit 只补设计中额外行为。

技能先走业务成功，再按设计扣费/放电。rechargeable 进度显示不是权限，真正执行前再次 IsCharged。失败、取消、目标失效和预测回正都不重复结算。

瞄准需要载体、位置、原生 Action/SG 与服务端校验完整链，不能只写一个 spellfn 并声称客机按键已经可用。

## 装备与恢复

OverrideSymbol 的目标/来源 build/symbol 各自来自真实资产；装备、卸下、皮肤和变身恢复沿原版对应路径。修饰来源只清自己的部分，不直接将玩家公共值恢复成一个固定默认数。

耐久耗尽是删除、破损保留还是可修复先确定；forgerepair 与 finiteuses 等支持范围按当前源码，不沿旧口诀排除。

## 验收

验证基础/升级伤害、边界等级、旧档、装备切换、普通/位面防御、投射物重复命中、资源不足、取消与真实客机技能链。
