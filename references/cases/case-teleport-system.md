# 设计案例：瞬移、召回、跨分片与急援

这四类移动使用不同合同，不能在同一 helper 中“缺组件就 Physics:Teleport 并返回成功”。本例保留机制选择与异常路径；旧模板中的同名原版 Prefab 覆盖、客户端直接调用主组件和跨分片假设不再采用。

## 机制与拥有者

| 需求 | 优先核对 |
|---|---|
| 同分片短距离瞬移 | blinkstaff 与实际物品/Action 的服务器流程 |
| 标记与召回 | recallmark 的原版宿主、记录格式与迁移边界 |
| 跨分片 | 原版迁移门户、Shard 状态、玩家离场/目标生成流程 |
| 到另一玩家附近 | 当前目标身份、同分片/异分片分支、合法落点与同意/权限政策 |

不要向所有玩家无条件添加 worldmigrator/recallmark 并假定一切就绪；对照目标组件的实际 Prefab 装配与生命周期。自定义物品使用私有 Prefab 名，不把自己的文件返回为原版 blinkstaff/wormhole。

## 同分片路径

服务端确认 caster、持有物、资源/冷却和目标，再寻找合法落点。水陆、墙、洞穴虚空、平台、骑乘/落水与可行走范围分别处理。瞬间改变坐标不自动处理原动作、跟随 FX、乘员与客户端预测。

blinkstaff:Blink 等签名按当前组件文档及调用者核对；不要把物品组件的方法当作玩家默认方法。缺少组件时返回明确失败，不能自动降级到未经检查的 Physics:Teleport。

## 召回与保存

保存稳定的分片上下文和位置/标记身份，不能把另一服务器的 GUID 当作本地实体引用。原地点被改造、海面平台移走或标记不存在时寻找合法替代点或拒绝。

标记是否随死亡、换角色、换洞穴、磁盘重启保留由玩法决定。组件自己 OnSave/OnLoad，不覆盖玩家/世界保存链。

## 跨分片

优先复用当前原版迁移入口，确认目标 shard 已连接、门户有效、目标准备和超时返回。发出消息不等于迁移成功；不能先扣费或销毁宠物后不管失败。

需要自定义协议时明确请求身份、权威拥有者、版本、确认、超时与恢复，不让两端同时最终发放同一实体。宠物、坐骑与容器内容分别定义迁移，不假定玩家移动会自动携带所有关联实体。

## 急援 UI 与输入

列表只展示当前可见目标，用稳定业务身份发送选择意图。客户端不能 self.owner.components.emergency_assistance:Activate(target)；真实业务在服务端处理器/动作中执行。

列表不每帧 Kill 并重建所有行。玩家加入离开/状态变化时更新，连续距离可用有边界刷新。面板通过真正 Screen 或 Controls 子树管理，默认焦点、取消和重复打开需要清理。

急援是否允许骚扰、跨距离、跨分片、目标幽灵或未同意由设计决定；按钮可点击不代表服务器准许。当前示例不夹带商店货币/击杀奖励逻辑。

## 验收

验证合法/非法落点、移动中目标、平台移除、资源不足、重复点击、门户失联、迁移超时、磁盘重启和真实远端预测。源码声明或本地主机一次成功不能替代这些路径。
