# UI 常见陷阱

当 DST UI 补丁在某个场景下工作正常，但出现重复、泄漏或影响错误层级时，请参考此文件。

如果路线本身不明确，请先阅读 `references/patterns/ui/ui-patch-patterns.md`。

## 快速排查

- 补丁运行了，但行为被错误的屏幕或控件所拥有
  - 检查是否错误地修补了错误层级
- 控件出现两次或持续重建
  - 检查构造函数重复问题
- 快捷键或回调在关闭后继续触发
  - 检查清理泄漏
- 主机模式正常但专用服务器崩溃
  - 检查本地全局变量和保护措施
- 按钮点击但游戏状态未正确同步
  - 检查 UI 与权威边界
- 控制器或键盘导航感觉不正常
  - 检查 `default_focus` 和 `OnControl(...)`

## 修补错误层级

常见错误：

- 为一个真正属于某个屏幕的功能修补 `frontend.lua`
- 为一个应该放在 `controls` 中的小型持久 HUD 子控件修补 `playerhud`
- 当真正的问题是 `playerhud` 中的屏幕弹出流或覆盖层顺序时，却修补了 `controls`

修复方法：

- 在编辑前，将功能映射到 `controls`、`playerhud`、临时控件、弹出屏幕或 `frontend`

## 构造函数重复

`AddClassPostConstruct(...)` 在每次后续构造函数调用后都会运行。

常见错误：

- 每次都盲目添加子控件，而不检查实例是否已经拥有它

症状：

- HUD 控件重复
- 同一面板上有多个按钮
- 补丁首次看起来正常，但在重建后会重复

修复方法：

- 将句柄存储在 `self` 上
- 使用 `if self.somechild ~= nil then return end` 进行保护

## 清理泄漏

UI 经常因为处理器存活时间超过控件而崩溃。

常见错误：

- 注册输入处理器、监听器或任务
- 从未在 `Close()` 或 `OnDestroy()` 中移除它们

症状：

- 屏幕关闭后快捷键继续触发
- 回调针对已销毁的控件运行
- 重新打开的 UI 响应多次

修复方法：

- 每个注册都对应一个明确的清理路径

## 在错误运行时使用本地全局变量

常见错误：

- 在也会在专用服务器上运行的代码中使用 `ThePlayer`、`TheFrontEnd` 或 `TheInput`

症状：

- 在监听服务器测试中正常工作
- 在专用服务器上崩溃或静默失败

修复方法：

- 使用 `if TheNet:IsDedicated() then return end` 保护本地 UI 代码
- 使用 `if ThePlayer ~= nil and ThePlayer.HUD ~= nil then ... end` 保护 HUD 访问

## UI 直接修改游戏玩法

常见错误：

- UI 按钮直接调用服务器专用组件
- 客户端控件读取 `inst.components` 而不是副本数据

症状：

- 主机模式正常工作
- 远程客户端不同步或无操作

修复方法：

- 保持 UI 本地化
- 在客户端上读取副本或网络变量
- 通过 RPC 或操作流程发送意图以进行权威更改

## 错误根节点或错误绘制顺序

常见错误：

- 在错误的根节点下添加全屏覆盖层
- 将 HUD 子控件添加到一个会被隐藏或排列在其他 UI 后面的分支

症状：

- 控件存在但不可见
- 弹出窗口出现在另一层后面
- 覆盖层裁剪或锚点不正确

修复方法：

- 检查 `playerhud` 的根节点，如 `overlayroot`、`under_root`、`root` 和 `over_root`
- 在附加子控件之前检查 `controls` 的根节点所有权

## 焦点和控制器问题

常见错误：

- 构建弹出屏幕时没有 `default_focus`
- 假设仅鼠标交互

症状：

- 控制器无法聚焦对话框
- 键盘确认或取消无效

修复方法：

- 设置 `default_focus`
- 当屏幕应该消费控件时实现 `OnControl(...)`
- 检查 `widgets/screen.lua` 和 `screens/redux/popupdialog.lua`

## 过度修补 `frontend.lua`

常见错误：

- 为一个可以作为普通屏幕或控件实现的功能修补顶级前端堆栈

风险原因：

- `frontend.lua` 拥有全局屏幕堆栈行为
- 在此处进行广泛修补可能会影响无关的菜单或屏幕

修复方法：

- 优先使用自定义屏幕加上 `TheFrontEnd:PushScreen(...)`
- 仅在真正需要屏幕堆栈或前端根行为时才修补 `frontend.lua`

## 透明度渐变陷阱

在 `scripts/frontend.lua` 中观察到官方警告：

- `"alpha"` 渐变模式可能会导致屏幕子控件在之后无法点击且视觉显示错误

实用规则：

- 不要随意在保持交互的屏幕上重复使用透明度渐变
- 在修补渐变行为之前检查现有的前端渐变流程
